# Private chat

Implemented on `feature/private-chat` from `767b034c`. This is browser-local chat privacy, with no changes to server logging, API monitoring, native inference or tools.

The **Private chat** checkbox beside the thread title defaults off. Enabling it keeps the current history, draft, model and attached inputs in memory. It drains saves already queued before activation, cancels the pending draft timer and starts a distinct ephemeral conversation. It does not flush the draft at activation. Earlier content already saved to the library remains there; remove that saved thread explicitly if desired. The header shows **Chats · Private**, including when the thread heading has scrolled away.

While private, messages, drafts, tool results, image recipes and generated PNGs never enter the chat/image IndexedDB stores or the legacy localStorage chat/model copies. The thread storage API also rejects private records defensively. The private record, model choice and active pointer are not persisted. Generated images use only the in-memory blob cache; their cards say memory only. Editing a private output stays private. Transferring its recipe into the public Images template workflow is disabled. Downloads and Markdown export remain explicit ways to keep content.

**New chat** while private discards the old private conversation and starts another private conversation. Opening a saved thread leaves private mode. Turning the checkbox off starts a new saved conversation; it never saves the private contents. These transitions require a discard confirmation whenever private messages, drafts or selected inputs exist. Cancel keeps everything in place. Typing, sending and toggling privacy are blocked during that confirmation. Generation and file reading must finish before changing mode.

Leaving the private conversation revokes its object URLs and drops cached PNGs. A copied public image is kept in memory if its original saved thread is deleted while the private copy is open; leaving private mode drops that memory copy without deleting other saved threads. Page hide clears private messages, drafts, input references and previews, and aborts any active chat request before a back/forward-cache snapshot. Refresh opens the last saved browser thread instead of restoring private content. Mode is per tab and is not remembered across reloads.

This does not erase earlier saved copies, explicit downloads/exports, server/tool logs, engine caches or operating-system/browser internals. Requests still reach Strata and enabled tools. Image inference uses the existing temporary-file cleanup path. The Images tab and browser-wide preferences remain separate from private chat; this is not a browser-wide incognito mode or a server zero-retention guarantee. The UI explains this scope. Saving must initialize successfully before the toggle is usable.

## Validation

CPU fixtures only, Chromium 154 on Windows; live remained available during implementation. Six screen sizes (320x568, 390x844, 844x390, 1280x844, 390x300, 320x256) each passed 20 private-chat and four real-refresh assertions. Tests instrument IndexedDB put/add and localStorage writes, verify zero private database writes, retain the original saved chat, refuse direct private-record persistence, test cancel/discard/New and check no sensitive marker after reload. The final 21-assertion suite at 390x844 also verifies private reference editing without database writes.

Six private model/lifecycle checks passed, including actual mock serving identity, unchanged saved model choice, file-reading guard and page-hide clearing. Existing model selector (26), saved threads (26), image generation/edit/archive/refresh (54) and mobile chat (33 at each of six sizes) regressions passed. A cold font-load timing failure in the selector's overflow measurement passed on retry; that fixture now waits for fonts before measuring layout. JavaScript syntax and diff checks passed.
