# Local edit fidelity and independent camera controls

2026-10-15, `fix/targeted-image-editing`, based on `151924083e44cd4b034100b477f3322b1468b094`. This follows a user report that a small black-fur-to-white correction redrew texture across the image, while camera presets appeared ineffective. The previous robot smoke tests did not establish precise fur editing or reliable novel views on complex scenes.

## Findings

The supplied original is a 1024x1024 stylized cat/mouse image, seed 826836895. Its PNG contains both native generator parameters and a Strata recipe; the clipboard result has no usable saved edit recipe. The exact original brush path was not available. Reproduction used an approximate brush selection above the viewer-left eye and the user's confirmed wording, “Change the selected area to white fur.” Image metadata is treated as data, never executable instructions.

The installed Qwen-Image-2.1-Turbo Q8_0 runner accepts the edit references, but full-frame mask conditioning can under-edit the small target while sharpening/retexturing the whole scene. A short prompt alone did not reliably recolor the patch, even after cropping. More explicit source/target color wording on a focused crop did produce white fur. This does not establish broad model compliance.

Camera-only side, rear and overhead tests with the same source/seed at 1024x1024, 8 steps, failed to establish the requested views: the composition largely stayed unchanged while texture/contrast changed. Separate low/front and low/rear tests using independent direction/elevation also largely retained the original view. An earlier very explicit overhead instruction mostly tilted the cat's head. Camera-plus-lighting testing changed tint more than viewpoint. Treat the current model's camera editing as experimental, not solved by the UI split. Text prompts were verified to contain the requested directions and elevations; this is not a missing-select-value bug.

## Local edit behavior

**Keep unselected areas unchanged** is checked by default for region edits. With no global camera/elevation/framing/lighting preset, the browser applies the model result only through the selected mask, at the original source resolution. The mask feathers inward by two source pixels; generated pixels never extend beyond its nonzero coverage. This avoids replacing the entire original with a re-render. Box edits also support protected compositing.

For a small brush selection (under 10% bounding-box area, with sufficient surrounding context), the browser sends a square focused crop and matching mask, generates a 512x512 patch, and places it back at the original coordinates. A crop spans approximately three times the selected extent, with at least a quarter of the short source dimension, clamped to the source. Larger selections stay full-frame. Original uploads remain in memory; a cropped source reference intentionally has different request bytes and provenance from the original file. The recipe records `preserveOutside`, normalized `crop` and `sourceSize`, as well as the existing region and actual final output dimensions. Coordinates alone cannot replay a brush shape; originals and a new selection are still required after import.

For a narrowly recognized request such as “Change the selected area to white fur,” a deterministic instruction helper names the original dominant black/white tone and the requested fur/hair color explicitly. It runs only for this unambiguous color/material phrasing, on focused protected brush edits, when more than 55% of selected samples are dark or light. Other instructions are not reinterpreted. The full effective prompt is visible before submission and recorded in the PNG, while `controlPrompt` retains the user's draft. This is a simple prompt expansion, not a hidden vision/chat call or a general semantic understanding guarantee.

Selecting any global preset disables local protection and focus cropping for that request, with a visible explanation. It must not silently crop or paste back a global camera/lighting change. The user can explicitly turn protection off. Finalization completes before the progress/busy state clears. The raw image API and chat image tool remain unchanged; this preservation step applies to UI Images results.

Pixel verification compares decoded browser pixels. The supplied original has partial alpha values (245–255), so browser canvas premultiplication/PNG round trips can change some underlying RGB components by one unit outside the edit. This is not a byte-for-byte original-file guarantee. On opaque fixture images every unselected final PNG pixel matched the original exactly. On the user's image, 6224 decoded pixels changed, none outside the selected bounds compared with the same browser round trip; mean brightness gain of changed pixels was 165.39 levels. The scene stayed visually intact while the selected black patch became white fur. The test selection approximates the user's brush, not their exact desired final boundary.

## Independent camera settings

View direction: front, three-quarter, side, rear. Camera elevation: eye level, high, low, overhead. Framing/zoom remains a third independent control. Direction prompts no longer force eye level, so front/low, rear/low or side/high can be requested together without contradictory wording. Lighting and Reset presets remain aligned.

Recipes store the new optional `editing.elevation` separately from `editing.camera`. Legacy camera values high/low/overhead are accepted and mapped to elevation when imported. Templates preserve current direction/elevation selections; defaults remain unset. Both camera controls are visibly experimental because the installed model can ignore the requested transformation.
