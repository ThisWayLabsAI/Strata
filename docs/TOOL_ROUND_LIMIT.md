# Tool round limit and final answer

The local installation uses `"mcp": {"max_rounds": 16}` in its two live and two development configs. The upstream default remains 8. Config changes require restarting the Python server. A round is one model response requesting server-managed tools; several calls can run in a round, so call count can exceed round count. This is independent of output-token and context limits.

After the final permitted round completes, Strata retains all results, removes every offered tool, and appends a request to finish the original answer using collected information, acknowledging gaps and failed lookups. It emits the existing `strata_mcp` limit event and runs exactly one final model pass. It does not execute further tools, even if the model still requests them. Plain chat, client-managed tools and tool runs below the cap retain their existing paths. Cancellation and image GPU restoration remain on their existing paths. The final pass uses the existing request generation limit and can still be stopped, truncated by context/output limits, or fail; it cannot guarantee a useful answer from every model.

The chat footer now says `tool limit reached (16 rounds); final pass without tools`, rather than claiming the answer stopped at the tool limit. Old saved messages keep their original footer. The synthetic final-answer instruction is request-local and is not inserted into the saved user transcript. A limit notice means the budget was exhausted, even if the final answer completes successfully. Raising the cap permits longer research but does not fix repeated searches or unreachable websites.

Mock validation: `python -m unittest serve.test_mcp serve.test_chat_images -v` passed all 45 tests on Windows. Tests cover streamed and nonstreamed final answers, last-result/error retention, the 16-round override, tool removal, bounded repeated tool requests, client ownership, cancellation at the limit/before final preparation and image lifecycle. JavaScript syntax and diff checks passed. No native GPU is needed for these tests. Evidence: `C:\AI\Strata-data\logs\mcp-budget-20261016`.

Deployment requires idle live, configuration backups, source fast-forward while stopped, the existing startup control, then health, `/mcp` settings, config semantic comparison and chat verification. Preserve keys, model paths, registry choices, GPU policy, packages, controls and scheduled-task settings. Local config backups include secrets and must stay local; never include them in Git bundles or commits.
