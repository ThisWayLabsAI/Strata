# Camera, lighting and region-guided edits

Updated 2026-10-15 with brush selection, reference-recipe reuse and generation progress. These optional controls are in **Images → Camera, lighting & edit region**. They work with the installed image backend and existing references. They do not yet add editing tools to chat.

The local-fidelity follow-up adds protected compositing, focused crops for small brush selections, and separate view direction/elevation controls. [IMAGE_EDIT_FIDELITY.md](IMAGE_EDIT_FIDELITY.md) supersedes the earlier region/camera limitations below where noted, including the user's cat-image reproduction and remaining model limitations.

## Use it

Submission feedback (2026-10-15): both operations need a written prompt; camera and lighting choices supplement it. Edit also needs source image 1. If Edit is disabled, the footer beside the button explains whether to upload a source, wait for file reading, or check reference support/API authorization. Invalid steps (whole number 1–100) or fixed seeds (whole number 0–9007199254740991) show persistent footer guidance and focus the field, opening its collapsed panel. New seed or Random can resolve a missing fixed seed. An unfinished Image URL only matters when importing it; it must not block an otherwise valid request. A reference URL must be imported before it becomes a reference.

Failures remain in the footer after transient notifications disappear, including authorization, network, unreadable responses and empty results. Prompt and references remain available for retry; requests are never automatically replayed. The progress bar and Cancel appear only during a pending request. No new image model quality claims follow from these UI checks.

Write the scene or requested changes in Prompt. Choose any camera, framing or lighting presets, then review **Prompt that will be sent**. The draft is kept intact; the selected instructions are added only to the request. The defaults are **Unchanged / prompt decides**, preserving the previous request prompt. Reset presets clears these choices. Selecting a preset never starts generation or changes the operation, source references, size or seed.

View direction: front, three-quarter, side profile or rear. Camera elevation: eye level, high angle, low angle or overhead. These are independent: choose low/front or low/rear, for example. Framing: close-up/tighter, medium shot, wide/farther back and full subject. These describe a generated view, not a calibrated camera or numerical optical zoom. The installed model failed to establish several requested views on the user's cat/mouse scene; both camera fields are marked experimental. New views and wider framing may invent hidden details.

Lighting: soft studio, overcast daylight, golden hour, dramatic side light, rim/backlight, high key, low key and neon/cinematic. Camera, framing and lighting instructions apply to the whole scene. They override conflicting camera/lighting wording in the draft. Accuracy depends on the model and prompt; they do not guarantee physically exact lighting or geometry.

For a targeted edit, select **Edit a source image**, upload the original as image 1, and enable **Mark an edit region**. Brush is the default tool: paint with mouse or touch, adjust size (2–30% of the image's short edge), or enable Erase brush marks to refine the selection. The red overlay previews the painted area. Undo stroke retains five strokes; cancelled pointer gestures restore the preceding selection. Clear region removes the selection. Describe what to replace/change in Prompt, then submit Edit image.

Box remains available. Select center works with either tool; in Box mode, focus the image and use arrows to move or Shift + arrows to resize. Enter/Space selects the center. Switching tools clears the previous selection. Changing tools or clearing mid-gesture is blocked until the pointer finishes, avoiding partial masks. Reset presets is aligned with the lighting dropdown in the two-column layout; mobile stacks the fields.

The original reference bytes remain unchanged. Brush appends a separate black-and-white PNG selection mask: white pixels identify painted targets and black pixels identify surroundings. Box appends a marked copy instead. Guides are at most 1024 pixels on the longest side. Instructions identify them as selection guidance, not scene/style references, and ask the model to omit all guide marks from the result. This uses one of the existing three reference slots, so a region edit allows at most two uploaded references. Inputs are never dropped to make room. Three references, an incomplete gesture, an unavailable source or a missing region produce a visible error before submission. The bitmap and five undo snapshots are memory-only and bounded by the guide dimensions.

Both tools guide the generative model. With **Keep unselected areas unchanged** enabled and no global preset, UI results now merge only selected pixels into the original, with inward edge feathering. Small brush edits use a focused crop to improve local attention. The final image keeps source resolution. Camera/elevation/framing/lighting presets apply globally and visibly disable this protection. With protection off, pixels outside the selection may change. Multiple disconnected brush marks are supported; model compliance inside the selection and identity preservation remain imperfect. See the fidelity document for alpha/round-trip limits and recipe provenance.

## References, templates and recipes

Changing/reordering image 1 clears an existing region when its source bytes change. Switching to Generate suspends the region and never sends its guide; switching back permits reuse only for the same source. During generation, presets, references and region editing are locked. Cancel uses the existing image subprocess/GPU cleanup.

Applying a starter, saved or result template preserves selected camera/lighting/framing controls, the region and current references. Saved templates keep their existing prompt/settings behavior; preset selections are separate controls and are not automatically stored in template-library entries. They are not automatically retained across page refresh.

UI PNG recipes optionally store whitelisted `editing` fields: `camera`, `elevation`, `framing`, `lighting`, normalized `region: [left, top, width, height]`, and `regionMode: "brush"` for freehand selections. Protected local edits also record `preserveOutside`, normalized `crop` and `sourceSize` when focused. Region coordinates bound the painted area; they do not contain the stroke shape or mask pixels. Older recipes without regionMode retain Box meaning; old camera high/low/overhead values map to elevation. `controlPrompt` stores the draft before generated control instructions, while `prompt` remains the actual generation prompt. Existing `templatePrompt` retains the reusable base treatment. Reference provenance includes the guide/mask's normalized hash and role, without embedding source bytes, local paths or URLs. Raw API image bytes remain unchanged.

Uploaded or browser-imported PNG references are checked for a Strata recipe. A reference with valid metadata offers **Load recipe** directly on its card; this loads the prompt/draft, seed and reported settings, preserves the current operation and every reference's bytes/order/role, and clears stale region selection. Uploading alone never overwrites the draft. Missing or invalid metadata is reported on the card without rejecting an otherwise usable image. Recipe content remains data, not instructions to execute. Reference requests still include only image data, name and role.

The standalone **Load recipe from PNG** picker remains available when no reference is needed. That explicit import retains its existing behavior: restore the recorded operation and clear references, requiring originals again for Edit. Both entry points restore the draft/presets without duplicating control instructions and require the region to be selected again. Coordinates alone are not sufficient to safely recreate a guide. Use as template continues to preserve current controls/references.

The generation footer displays a native indeterminate animated progress bar while the request is pending, including queue/preparation time. No percentage or estimated time is invented. It clears on success, error or cancellation; assistive technology receives the progress label/busy state. The fixed action footer remains visible.

## Implementation and checks

`serve/web/image-edit-controls.js` owns preset instructions, preview, pointer/keyboard input, source invalidation and request preparation. It adds a bounded guide to the existing `references` contract; no new API, model, encoder, package or machine-config setting is required. The default tool and Images paths keep their previous request prompt/reference bytes when controls are unused.

Checks passed: 22 Node tests (16 existing recipe/template tests plus 6 control contracts), 33 Python image/reference regressions and 735 Chromium fixture checks. Each of 320x568, 390x844, 844x390, 1280x800 and 390x300 ran 26 new editing checks plus 23 template-context, 21 reference, 25 recipe, 33 mobile-chat and 19 chat-image checks. Coverage includes guide pixels, normalized coordinates, touch-event mapping, keyboard movement/resize, cancelled gestures, duplicate-free recipe reuse, reference limits, unchanged originals, busy-state locks and default requests. A real mouse drag was checked and the mobile screenshot visually reviewed. Actual iOS/Android gestures and keyboards remain untested.

Brush/reference-recipe/progress follow-up: 23 Node tests and 777 Chromium checks passed across those same five viewports (27 focused checks on narrow screens, 28 on wider screens, plus the existing 26 edit, 23 context, 21 reference, 25 recipe and 33 mobile checks per viewport). Checks inspect actual mask pixels, erase/undo/cancellation, preserved source bytes, recipe actions and operation retention, reference limits, progress lifecycle and exact lighting/reset alignment. No Python backend changed; the preceding 33 Python checks remain the recorded backend regression run. A native mouse brush gesture was inspected. Actual phones remain unverified.

Hardware checks use the existing authenticated live image API, with no second GPU server or service restart. Original Qwen's configured Qwen-Image-2.1-Turbo Q8_0 CUDA backend generated 512x512 edits at 8 steps. Seed 720 tested three-quarter/full-subject/rim presets (12.84 s endpoint latency); inspection showed only a modest viewpoint change and weak visible rim lighting. Seed 721 tested a marked head replacement (10.72 s): the robot's head became a green sphere, the body/background stayed visually similar, and the guide outline was absent. These first requests used keep policy. A separate side-profile/full-subject/neon test, seed 720, took 12.77 s and used unload policy; inspection showed a clear side view and cyan/magenta illumination. Subsequent chat returned READY after both runs, with no request remaining in flight. This is visual inspection, not pixel equality or a quality benchmark. Other models/backends were not re-tested for this frontend-only increment.

The follow-up Brush test used a separately painted black-and-white mask, seed 720, 512x512 and 8 steps (10.89 s endpoint latency, keep policy). The selected head became a green sphere, with similar surrounding body/background and no mask visible in the result. Subsequent chat returned READY and no request remained in flight. This is one short visual smoke test, not proof of exact outside-mask preservation.
