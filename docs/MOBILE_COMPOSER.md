# Mobile composer and control spacing

Implemented on `fix/mobile-composer`, based on deployed `8e8eaa62`, in response to four Android/Brave screenshots. Browser fixtures validate layout; actual device testing remains with the user.

On mobile layout the composer starts as one reading row: **Ask anything…**, **Ask a follow-up…**, or **Continue draft…**. Tap it to expand and focus the input. The chevron collapses it without clearing the draft. Sending a valid request collapses the composer and dismisses input focus so the response has more room. Stop occupies the same 44px action position as Send; the two are never displayed together. The compact row retains Stop during generation. Expanding to draft the next question while the reply streams keeps the input expanded at completion. Validation failures preserve the current input state.

**Options** opens a bounded, scrollable panel containing the model selector, image opt-in/settings, New and Export. Desktop keeps its expanded composer and existing controls. Mobile attachment selection and image-recipe discussion expand the composer; selecting an image reference also opens its settings. Model/image request semantics, drafts, private mode, stored threads and GPU ownership are unchanged. New and Export in Options invoke the existing guarded actions. Escape closes the panel and returns focus to Options.

Private-discard actions have a 12px gap and stack on screens up to 600px; Discard has a destructive border/text style. The image operation selector and **Choose image** use separate rows with spacing. File-picker explanation is under a Help disclosure. Dialogs and action controls retain at least 44px targets.
