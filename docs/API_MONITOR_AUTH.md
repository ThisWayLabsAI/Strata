# Shared Chat and API Monitor key

API Monitor uses Chat's JSON-encoded `strata.apikey` local-storage setting on the same browser origin. A saved Chat key authenticates a newly opened `/api-monitor` automatically. Manual Connect in Monitor saves the same shared setting, and open Chat/Monitor tabs follow storage changes. Chat reads the current shared key for each request; its key field also updates when Monitor changes it.

For existing Monitor users, the old `strata.monitor.key` session setting is a fallback only when the shared entry is absent or browser storage is unavailable. An explicitly empty, malformed or wrong-type shared value does not revive the old key. Cross-tab removal/clear drops the legacy fallback. Manual entry stays usable in memory if storage throws. A delayed response from an old-key request cannot overwrite the newer connection state, including while request details are loading.

The fallback form explains sharing and fits narrow screens with 44px input/Connect controls. Refresh both pages to load the updated scripts. Localhost and Tailscale addresses have separate browser origins, so their keys remain separate. Sharing changes browser preferences only; it does not change the server key, API authorization, private-chat storage or model/GPU behavior. Manual Monitor entries now have the same browser persistence as Chat entries when local storage is available.
